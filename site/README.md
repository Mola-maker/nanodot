# Nanodot product site

The product pages are static HTML, generated Dot tokens and system fonts. English and 简体中文 share the same page; language and theme preferences stay in localStorage. No credential form, remote demo, inference or analytics is included. `site/assets/dot-idle.svg` and `nanodot-icon.svg` are exact offline copies from `assets/brand/`; recopy their original files when regenerating the brand. `dot-tokens.css` is generated by `scripts/gen-ui-tokens.py`, never hand-edited.

`downloads.json` records temporary P0 Actions artifacts. Each URL and SHA-256 refers to the same **outer GitHub ZIP**, not an inner installer. Login, UTC expiry, debug/ad-hoc/unsigned status and P0 capability boundaries are shown. Refresh only from actual verified build evidence. Historical `legacy.html` keeps its original `legacy-style.css` / `legacy-site.js`; it, promo media and the old Python-line site are excluded from the product build.

## Build and local checks

Use Node 22. Existing documentation defaults and `DOCS_BASE` remain available; only the gateway build selects the new optional override:

```sh
NANODOT_DOCS_BASE=/docs/ npm --prefix website run docs:build
node scripts/site/build.mjs
node --test site/tests/*.test.mjs
npm --prefix gateway test
```

`buildSite({outDir, docsDir})` copies the compiled docs into `/docs/`, product pages and local Dot assets into the dedicated output (default `gateway/public/`). It checks actual filesystem ancestry before deletion: within the repository only `gateway/public` is permitted, while separate external temporary outputs remain supported. Source trees and compiled-docs inputs cannot overlap the output. It does not deploy. Use a `/docs/` documentation build for this root deployment; the default `/nanodot/docs/` remains for the existing destination.

Wrangler serves a real custom 404. `/v1`, `/v1/*` and `/healthz` always run the Worker first, retaining no-store JSON API errors even for browser navigation. The Node route test uses actual local Wrangler ASSETS with AI omitted; it cannot perform inference. Gateway tests cover configured project authorization with remote bindings disabled. An authorized local socket is required for these checks. The configured local route test uses the production handler with a throw-on-call AI shape for discovery/auth only.

Pending CI integration: `.github/workflows/pages.yml` still uploads raw `site/` at `/nanodot/`, without inserting download cards and with a different path base. It is not the gateway product assembly. The separate deployment task must update this build/publication path before offering manual publication of the new candidate; the root gateway requires the verified `gateway/public/` output.

## 简体中文

产品页采用静态 HTML、自动生成的 Dot tokens 与系统字体。中英文、深浅外观均可切换，偏好仅保存在浏览器 localStorage。离线图形由 `assets/brand/` 原文件复制；品牌更新后重新复制，不能手改自动生成的 tokens。产品构建不包含旧演示或宣传素材。

下载清单的链接和 SHA-256 都对应 GitHub 外层产物 ZIP，不是内部安装包。页面说明登录要求、UTC 到期、debug/ad-hoc/未签名状态与 P0 能力边界，刷新时必须以真实构建证据为准。iOS 未签名 app/archive 不能直接安装。

以上命令构建文档与产品站，并在真实本地 Wrangler ASSETS 上检查 404 与 API JSON 路由。`NANODOT_DOCS_BASE=/docs/` 是新根部署的可选覆盖，已有 `DOCS_BASE` 及默认 `/nanodot/docs/` 保留。删除前先核对真实文件系统路径：仓库内只允许输出到 `gateway/public`，仓库外独立临时输出仍可用；输出不得与源码树或已编译文档输入重叠。不部署、不收集 key、不调用真实模型。
