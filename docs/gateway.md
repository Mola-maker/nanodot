# Private Workers AI gateway

The gateway in `gateway/` supplies private authentication, a durable free-tier admission gate, an allowlisted model catalogue, chat/vision protocol adapters, and bounded voice protocols. Chat can attempt inference when the configuration is valid. Transcription can attempt inference after bounded WAV validation. Chinese speech remains disabled with `503 tts_unverified` and consumes no admission budget until actual verification. The source product site is built into the asset staging directory separately; source completion does not establish a live deployment. This work does not change existing app connections or nanoMuse Cloud.

The intended origin is `https://molamaker.si`, with OpenAI base URL `https://molamaker.si/v1`. These addresses describe the intended deployment, not a verified live service. Existing Cloud and third-party providers retain their real origins.

## Project credentials

An operator supplies independent project credentials to authorized clients. This gateway does not create user accounts, registration, a Hub or conversation sync. A Cloudflare control token belongs only in the deployment environment and must never be entered as a project credential.

`GATEWAY_KEY_HASHES` is a Worker secret containing a JSON object of stable, nonempty client IDs mapped to 64-character SHA-256 hexadecimal digests of their project credentials. Store the original credential only in the client's existing encrypted storage. Never publish a shared key, embed it in an APK or website, or record it in source, logs or documentation. Duplicate digests and malformed or empty configuration fail closed. Assign distinct credentials to distinct clients; the server derives identity from the matched hash rather than a client-supplied ID.

API requests use the `Authorization: Bearer` header. Missing or incorrect authorization returns JSON `401 unauthorized`; credentials in query parameters are refused, even alongside a valid header. Authentication never reads the request body. The gateway emits no request-body, credential or URL logs, and Worker observability is disabled in the staging configuration.

## Admission limits

`FreeGate` uses the SQLite Durable Object migration `new_sqlite_classes`. All AI routes must use the single namespace object named `global-free-tier-v1` (exported as `FREE_GATE_NAME`); sharding by client, model, route or region would defeat the global budget.

The gate admits at most **40 AI attempts per UTC day across all clients**, and at most **12 per authorized client in a rolling 60-second window**. It checks and increments both counters inside one synchronous SQL transaction before inference. A denial returns `allowed: false` with a positive integer `retryAfterSeconds`; the chat handler translates this into HTTP `429` and `Retry-After`. When both limits apply, the retry time covers both. Failed or cancelled attempts stay counted: there is no refund method.

The daily counter resets at 00:00 UTC. A rolling window continues across midnight. Expired minute entries are deleted on admission, and the single daily row is replaced when the UTC day advances. Persistent counters survive object eviction. Backwards server-clock movement cannot restore spent quota. Only authorized client IDs, counters and admission timestamps are stored; there are no prompts, responses or chat history.

The internal `admit(clientId, nowMs)` RPC must receive the authenticated identity and the Worker's `Date.now()`, never request fields or headers. Chat validates its model, body, format and budgets first, then calls admission immediately before attempting AI. Unverified Chinese speech does not call admission.

These are application request limits, not a Neuron meter. Cloudflare's account-wide Free allocation is **10,000 Neurons per day**, resetting at 00:00 UTC; other applications on the same account also consume it. The actual logged-in target must be verified as Workers Free before enabling inference. Do not purchase, upgrade, switch automatically to Paid models, or alter another project's billing. If the target is not Free, keep inference disabled. See [Cloudflare Workers AI pricing](https://developers.cloudflare.com/workers-ai/platform/pricing/).

## Responses and configuration

API requests first check the secret plus `AI`, `ASSETS` and `FREE_GATE` bindings. Missing or invalid configuration returns JSON `503 gateway_unconfigured`, before checking authorization. With valid configuration, authentication precedes route and method selection; unknown `/v1` routes return JSON `404`, and unsupported methods on inference routes return JSON `405`. API failures never fall through to HTML assets. Error responses are not cached.

`GET /healthz` reports only `deployed`, `configured` and `inferenceEnabled`; it neither calls AI nor spends quota. It returns `503` for incomplete configuration and reports `inferenceEnabled: true` when the configured chat handler can attempt inference. This is code/configuration readiness only. A healthy response does not verify the account plan, model access or live inference. Non-API GET/HEAD requests use the `ASSETS` binding; the Worker runs first for `/v1`, `/v1/*` and `/healthz` so assets cannot bypass API routing. Missing product pages serve the custom 404 with status 404.

## Chat and image wire protocol

Authenticated `GET /v1/models` returns an OpenAI list with `id`, `name`, and `architecture.{input_modalities,output_modalities}`. The catalogue contains Qwen text→text, Gemma text+image→text and Whisper audio→text. Whisper transcription is implemented; live Mandarin intelligibility is still pending. MeloTTS is omitted until Chinese output is actually verified. See the current primary model schemas for [Qwen](https://developers.cloudflare.com/workers-ai/models/qwen3-30b-a3b-fp8/), [Gemma](https://developers.cloudflare.com/workers-ai/models/gemma-4-26b-a4b-it/) and [Whisper](https://developers.cloudflare.com/workers-ai/models/whisper-large-v3-turbo/).

`POST /v1/chat/completions` accepts only `@cf/qwen/qwen3-30b-a3b-fp8` and `@cf/google/gemma-4-26b-a4b-it`. A JSON body contains `model`, nonempty `messages`, optional boolean `stream`, and an optional token budget (`max_completion_tokens` or `max_tokens`). Omitted stream is false; omitted output budget is 2,048. Both budgets, if present, must agree. Qwen receives `max_tokens`; Gemma receives `max_completion_tokens`. Only validated messages, budgets, sampling (`temperature`, `top_p`), function definitions and Gemma usage-stream options reach the binding. Unknown top-level fields are discarded. Non-text response formats and non-auto tool choice are refused before admission.

The body limit is 4 MiB, text context (including tool definitions and arguments) is 16,000 JavaScript characters, and output is at most 2,048 tokens. Only Gemma user content may contain an `image_url` part: its URL must be a PNG/JPEG base64 data URL. Remote URLs are never fetched. One image may be sent, with at most 2 MiB decoded bytes and dimensions of 1–1280 pixels. The server validates container framing and dimension headers; the client must re-encode images within those limits. Invalid model, content, image or format receives JSON `400`; an oversized body receives `413`, all before quota admission.

Both models accept documented function definitions. Qwen's verified schema supports simple properties containing `type` and `description`; unsupported schema keywords are refused. Gemma accepts OpenAI function definitions and assistant `tool_calls` plus `tool` results with `tool_call_id`. **Qwen tool history is currently refused with `400`** because its published message schema does not establish their encoding. Reasoning-history input is refused for both models until its encoding is verified; generated reasoning is preserved in output. Android omits this unsupported history field only for the parsed `https://molamaker.si` origin (default/443 port), even when bundled model enrichment enables reasoning. Other origins retain their existing echo rules. Use Gemma for a verified agent tool round trip. There is no automatic model substitution. The gateway returns function calls and never executes tools. Care-mode callers send `tools: []`.

Non-stream responses use `choices[].message`, completion metadata and upstream usage. Streaming responses use SSE `choices[].delta` chunks, preserving text, reasoning, function calls, usage and stop/length/tool finish reasons, followed by exactly one `data: [DONE]`. The documented [native Workers AI response stream](https://blog.cloudflare.com/workers-ai-streaming/) is adapted from `response` text events and explicit `[DONE]` into the same shape. A native `[DONE]` establishes completion; ordinary EOF does not. Empty streams, invalid events, upstream errors and truncated streams emit a sanitized SSE `error` and close without a fabricated stop or `[DONE]`. UTF-8 decoding preserves text across arbitrary byte splits. Empty tool arrays, tool IDs/indexes alone and empty reasoning fields do not establish output; reasoning text and function name/argument fragments must have valid types before they count.

HTTP errors remain JSON: `401` for credentials, `429` plus `Retry-After` for quotas, `503` for unavailable configuration/model service. Errors after streaming headers are sent become SSE errors. Client abort and `reader.cancel()` release and cancel the local upstream reader. Cancellation cannot guarantee that Cloudflare stops already-started inference or billing, and no admitted attempt is refunded.

## Local verification

Use Node 22 and the committed public-registry lockfile:

```sh
npm --prefix gateway ci --registry=https://registry.npmjs.org/
npm --prefix gateway test
npm --prefix gateway run typecheck
npm --prefix gateway run dry-run
```

Tests use the current Cloudflare Vitest plugin, real local SQLite Durable Objects, randomly generated test credentials, and `remoteBindings: false`. They perform no real model calls. Shared wire fixtures are also consumed through Android’s actual `ProviderFactory.streamMessage` and `OpenAIModelsApi` in `GatewayProtocolTest`; no substitute client parser is used. Do not enable remote bindings in tests. Dry-run bundles configuration without supplying a secret or deploying resources; successful bundling does not establish readiness for production.

Implementation references: [SQLite transactions](https://developers.cloudflare.com/durable-objects/api/sqlite-storage-api/), [SQLite migration](https://developers.cloudflare.com/durable-objects/best-practices/access-durable-objects-storage/), [Worker asset routing](https://developers.cloudflare.com/workers/static-assets/binding/) and [Cloudflare Vitest integration](https://developers.cloudflare.com/workers/testing/vitest-integration/write-your-first-test/).

## Bounded voice wire protocol

`POST /v1/audio/transcriptions` takes multipart `file`, `model`, optional `language`, and optional `response_format=json`. The only model is `@cf/openai/whisper-large-v3-turbo`. The bounded whole body is at most 4 MiB; the independent WAV is at most 2 MiB, complete RIFF/WAVE with PCM16, 16 kHz, mono, nonempty, and at most 30 seconds. Container chunk sizes, byte rate and frame alignment are checked locally. A malformed/unsupported WAV or field returns `400`; excess file/body bytes return `413`, before admission. Duplicate fields and unknown controls (including prompt) are refused. `zh-CN`/`zh-Hans-CN` normalize to `zh`; no translation is requested. The binding receives the **whole WAV** as base64 and `task=transcribe`, then returns `{text, language?, duration?}` using its documented `transcription_info`. Error JSON, malformed output and upstream failure return sanitized `503`, never fake text.

`POST /v1/audio/speech` remains unavailable and absent from the audio-output catalogue unless both `TTS_ZH_VERIFIED=true` and the recorded exact `TTS_ZH_LANG` are configured. The staging configuration explicitly keeps the flag false. Chinese and mixed Chinese/English MP3 must both fully decode with positive duration and pass human listening before an operator enables production. Schema inspection or mock bytes do not establish this. [Cloudflare MeloTTS](https://developers.cloudflare.com/workers-ai/models/melotts/) documents `prompt` and `lang`, without an enumerated Chinese value or voice/speed/format controls; the exact Chinese language string must come from the later live experiment.

Once verified, speech accepts only `@cf/myshell-ai/melotts`, `input` of 1–500 JavaScript characters, `voice` equal to that model ID or project alias `default` (omitted selects default), `response_format=mp3` (default), and speed absent or exactly numeric `1`. Other voices, formats, speeds and fields receive `400` before admission. Both aliases map to the verified model language with no invented speaker parameter. The documented byte/base64 output is checked for bounded MP3 framing and served as `audio/mpeg`; framing is not a substitute for the live decode/listening gate. Both voice handlers use the same global admission object as chat, immediately before their single AI call. Aborts discard late results; admitted failures/cancellations remain counted.

Android uses its actual `VoiceProviderFactory` and versioned OpenAI voice paths. Blocking voice IO has a cancellation watcher that cancels OkHttp. Read-aloud stop/pause cancels the active utterance while retaining the queue worker; generation checks discard late provider bytes and prohibit cancellation from triggering device fallback. Ordinary provider failure retains the existing system fallback behavior. Until cloud Chinese speech is verified, explicitly select and verify a system Chinese voice on the device. Device speech is not cloud MeloTTS; local JVM fixtures do not prove an installed Chinese voice or audible playback.

## Later live audio acceptance (Task6)

`scripts/gateway/verify-audio.mjs` defaults to **no calls**. Live mode requires explicit Workers Free confirmation, a nonprivate fixture/provenance hash, a shared Task6 JSON ledger (`totalAttempts`, `attempts`), credentials from environment, and an output directory. It reserves each attempt exactly once before HTTP dispatch; failures, cancellations and HTTP refusals are not refunded, and no retries occur. The combined Task6 live budget is at most **15 attempts**, including checks run elsewhere; all live tools must use the same ledger. This conservative local attempt count is distinct from the server's 40/day gate and from Neurons.

The prepared Mandarin WAV is offline eSpeak synthetic speech, not a human recording, and real ASR is still unrun. ASR mode saves the actual transcript and leaves intelligibility review pending. Candidate mode requires a **distinct private operator probe** URL and dedicated nonpublic operator credential, plus explicit confirmation that it binds the **actual same production `FreeGate` namespace / `script_name` and `global-free-tier-v1` object**. Task6 must review and create/deploy that temporary probe; this commit supplies no public probe route and deploys nothing. The production flag/catalogue remain disabled during candidate testing. The probe imports the same bounded speech handler with the operator's candidate language; probe success alone is not production verification.

Candidate and verified-production modes each make one Chinese and one mixed synthesis request, require `audio/mpeg`, save the actual bytes, run `ffprobe` for codec/duration and full `ffmpeg -xerror` decode, then leave listening pending. `--stage listen --listened-chinese-and-mixed` records the human's explicit listening confirmation only for those decoded files with matching hashes. The script never changes production variables, creates credentials, deploys resources or claims listening automatically. Missing decoder tools fail before synthesis. Production acceptance must be rerun after the approved language/flag are configured; candidate evidence, disabled production, and verified production evidence are separate stages. Run `node scripts/gateway/verify-audio.mjs --help` for exact options; credential values never belong in command arguments or reports.

## Product site build

The bilingual static product pages in `site/` describe current P0 downloads separately from preview gateway, orb and care source. All six downloads are temporary GitHub Actions artifact ZIPs requiring GitHub sign-in, with UTC expiry and ZIP-scoped SHA-256. The unsigned iOS device app/archive cannot be installed directly and is not an IPA or TestFlight release. The P0 builds do not contain the new gateway/orb/care integrations.

Build with Node 22: `NANODOT_DOCS_BASE=/docs/ npm --prefix website run docs:build`, then `node scripts/site/build.mjs`. The optional `NANODOT_DOCS_BASE` overrides the root gateway documentation base without changing the existing `DOCS_BASE` behavior or `/nanodot/docs/` default. The exported `buildSite({outDir, docsDir})` copies compiled docs to `/docs/` and original offline Dot art to the dedicated output, default `gateway/public/`. Before deletion, the builder checks actual filesystem ancestry, allows only `gateway/public` inside the repository and preserves separate external temporary outputs; source trees and compiled docs cannot overlap the output. It does not deploy. Run `node --test site/tests/*.test.mjs` and the gateway suite; local route checks need a local listening socket, omit AI bindings and never invoke a real model.

The connection guide accepts no credential input. The privacy page explains user-triggered image/audio transmission to Cloudflare, project payload non-persistence and the supplier’s own data policies. Existing Cloud/provider data flows remain separate.

## Optional client connection

The own-key catalogue offers **Nanodot · Workers AI** (`nanodot-workers`). Its `verified` month records a source/protocol review, not a live-service check. Android, iOS and desktop account/own-key screens offer the project-key entry; the Web console offers it on **Connections**. A dedicated operator-issued project key is required. Existing Cloud sign-in, tokens, origins, avatars, groups and selected models stay in place when this connection is added. New-install defaults also stay in place until real acceptance.

The phones wait for provider configuration to load, then create an independently owned UUID with the canonical origin and OpenAI Chat Completions format. Reconnects reuse that UUID rather than creating another provider. Android uses its existing encrypted provider repository; iOS uses its existing per-instance Keychain helper; desktop uses the harness credential store with a UUID-specific reference. The Python runtime saves metadata to `gateway-profile.json` and the key to its existing encrypted vault under a UUID-specific reference. No key is stored in client assets or profile metadata. A failed model refresh retains old model entries. iOS, desktop and Python validate a successful list before replacing their stored key; Android retains its repository's existing refresh behavior.

Model-list `architecture.input_modalities` and `output_modalities` determine which models take images or audio. Qwen's name does not make it a vision model; Gemma is offered for images only when the list declares image input. Whisper is a voice model, excluded from desktop/Web chat pickers. Chinese TTS remains absent while the production gate is false. Desktop/Python currently record audio model metadata; this change does not add a new desktop/Web microphone or playback implementation.

Connecting is separate from choosing a model. On phones/desktop, choose from the existing model settings or the explicit “Use it for” offer. In the Web console, **Connect with project key** saves only the independent connection; **Use selected gateway model** explicitly selects a listed chat model. Gateway previews and selections cannot borrow the prior slot's key, even when the origin is entered through the custom form. The runtime's authenticated `POST /api/connections/gateway` accepts `api_key`; the ordinary explicit model-selection route then resolves the independent vault reference. An implicitly inherited project key cannot follow a separately configured Python embedding origin; an explicit embedding key stays unchanged. There is no account registration, anonymous inference, or Cloud-token migration at this origin.

Local JVM, Node and Python fixture tests establish storage/protocol behavior. iOS XCTest needs macOS and compatible native dependencies. Separate actual model-list and text-SSE acceptance on Android, desktop, Web and iOS remains pending Gateway Task 6; one platform's success does not establish another's. Fixture voice requests are not actual ASR or Chinese TTS acceptance.
